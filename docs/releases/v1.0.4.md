# v1.0.4

本版修复两个文件操作边界缺陷，并补充持续采集和自动化任务的运行批次约定，统一日期、批次与成果版本的含义。

## 文件操作修复

- 删除记录读写统一使用64 MiB上限。执行前为完整清单和正常恢复/清除期间的状态增长预留容量，超限时在创建锁、隔离区和移动文件之前拒绝，避免隔离成功后恢复工具读不了记录。
- 恢复或清除旧批次时同样先检查重新编码和状态增长预算；容量不足时保留原清单与隔离内容，不先写入中间状态再报错。
- 规则生成器拒绝以主根AGENTS.md或PROJECT_RULES.md为首组件的布局，防止生成规则文件后，其下声明的目录无法创建；保留子项目内合法同名目录或原件文件。
- 不改变已有计划/清单的schema_version或CLI参数。此前已产生的超限记录不自动迁移，异常或不完整操作仍需按原有边界核查。

## 分类与批次约定

- 日期用于查找，运行批次区分独立执行，成果版本区分修订；同日同用途不自动归为同一批次。
- 持续采集或运行的输出可按已确认方式在业务位置内分批，也可保留稳定路径并关联运行标识；只补问缺失约定，不重启新项目问卷或强建目录。
- 独立重跑分别保留产物及状态，明确续跑才复用原批次；跨日续跑记录实际时间，不在午夜自动改名或迁移。
- 同次PPT/PDF及配套材料保持成套，跨日交付沿用约定批次；明确需要自包含交付包时，允许复制必要依赖为快照并注明维护源。
- 澄清不做数据分析不等于不需要代码或运行数据；各项相关未知需求逐项确认，环境另问。
- 技能入口、操作说明、目录参考、示例、多项目说明和生成的交付规则同步上述约定，不增加程序化问答门禁。

## 验证

- 完整Windows回归共191项：190项通过，1项因符号链接权限不足跳过；较v1.0.3新增7项回归，覆盖记录容量及旧批次兼容性、规则文件保留路径及合法嵌套名称。
- 两处代码缺陷先通过新增用例复现失败，再验证修复；独立审查发现的旧记录边界也补充了恢复/清除的拒绝无副作用检查。
- 五组独立文字演练覆盖批次确认、失败重跑及跨日续跑、跨午夜成套交付和自包含快照、开发与分析区分、只读盘点。未使用真实用户弹窗或业务数据，文字验证不保证所有运行环境中的对话行为。
- 维护仓库与全局安装的16个技能文件逐文件核对一致，当前版本均为1.0.4。

## 版本与兼容性

- VERSION、README、使用说明和技能metadata.version统一为1.0.4，本地全局安装同步同一技能内容；历史发布记录保留原版本号。
- Python 3.9+、标准库依赖和Windows写操作范围保持不变。批次规则不自动整理既有业务文件，也不提供后台监听。

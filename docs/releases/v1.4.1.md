# v1.4.1 管理方式确认与审查修复

版本日期：2026-10-02（Asia/Shanghai）。

## 变更

- 多个独立项目的管理方式成为与目录语言同等的适用必答项：确认位置和操作后，先选择同一工作区统一管理或各自独立维护。已有明确覆盖目标的选择不重问；单项目及 src/docs 等功能目录跳过此题，未答不默认布局。
- 统一管理保留工作区主根登记；各自独立时，每个项目根维护完整 AGENTS.md 和 PROJECT_RULES.md，使用各自根的基础 plan/apply，环境与成果路径也相对各自根。操作说明及当前交互场景同步分流，不建立共同父目录登记。
- 修复移动回退日志的硬链接写入遗漏：回退规划、打开日志后和每次追加前检查日志链接数，拒绝多链接日志，避免连带修改其他位置。普通数据文件的硬链接移动与回退保持兼容。
- 修复项目登记对已有路径引用的识别：兼顾原始路径和本工具生成的 Markdown 转义形式，防止同一路径的新旧规则并存；保持路径身份、名称边界和明确 before 迁移的字节保留。
- 修复 Markdown 链接核对：正确处理链接文字中的代码格式、代码中的注释标记以及标签内跨行的代码或注释；代码与注释中的伪链接仍忽略，遮蔽内容不会把分隔片段拼接成链接。
- 精简全局职责与重复流程说明，全局 AGENTS.md 负责适用的通用工作流和护栏。保留用途与状态分类、完整项目规则、变更记录及状态归档要求。
- 增加相关回归，保持 20 个安装文件、现有 CLI 与 schema，不引入第三方运行依赖或后台监听。技能升级不自动改写旧项目。

## 验证

- 本次发布准备在 Windows、Python 3.11.15 重新运行 `python -B -X utf8 -m unittest discover -s tests -p 'test_*.py' -v`：共 280 项，279 通过、1 跳过，无失败或错误。跳过项为 `test_safe_delete.SafeDeleteTests.test_file_symlink_is_not_followed`，原因是创建符号链接夹具返回 WinError 1314 权限不足。
- 相比 v1.4.0 增加 11 个行为测试方法；缺陷修复阶段已逐项验证失败到通过。独立代码复核确认五项问题已处理，技能仍为 20 个文件，6 个脚本的 CLI 声明不变。说明文件中的能力范围与实际有限 Markdown 核对保持一致。
- 两份技能均通过 quick_validate，维护源与安装副本全部 20 个文件的路径及 SHA-256 一致。6 个脚本通过 Python 3.9 语法解析；本地链接、章节锚点、9 个 JSON 示例及 git diff --check 通过。语法检查不等于在 Python 3.9 运行过回归。
- 发布前已完成管理方式的文字演练和独立项目临时夹具中的基础 plan/apply；审查修复后已独立复核统一、独立、单项目、记录维护、只读和等待等分支。这些是此前功能验证记录，本次未重新执行全部文字或实物场景，具体范围见[审查修复任务](../superpowers/plans/2026-10-02-audit-fixes.md)和[管理方式任务](../superpowers/plans/2026-10-02-management-mode-question.md)。

验证分别覆盖工具行为、所列文稿与实际检查范围，不构成通用 Markdown 解析、自动语义识别或未来所有操作的执行保证。

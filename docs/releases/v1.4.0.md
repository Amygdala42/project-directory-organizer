# v1.4.0 项目持续维护

版本日期：2026-10-02（Asia/Shanghai）。

## 变更

- 增加按项目采用的持续维护方案，保留“归属 → 用途与状态 → 关联 → 位置 → 命名”的分类顺序。用户或适用规则明确采用后，将任务记录、完成回填、状态归档和运行产物约定写入项目实际规则。
- 区分全局 AGENTS.md、项目 AGENTS.md 和 PROJECT_RULES.md 的职责：遵守适用全局工作流，项目入口保留介绍、约束、简短真实进展和任务链接，项目规则集中保存目录与维护主约定。修改当前项目不顺带改写全局配置。
- 以 note、tasks、tools 表达调查决策、任务过程和工具说明三类记录。devlog 及各类 archives 是可选布局，已有合适目录可复用，不强建目录套件；工具源码和工程依赖仍在其维护位置。
- 已采用项目在实际改动前复用或创建任务记录，完成或中止后回填结果、验证与下一步。小改动可简短追加，同一任务复用记录；只读不写记录，记录自身更新不递归产生新记录，也不增加额外确认轮次。
- 归档依据完成、被替代或失效状态及引用关系，不依据文件年龄自动搬迁；旧但有效的规范保留在维护位置。归档时保护配套关系并更新入口与引用。
- 日志、执行/恢复凭证、临时材料和缓存按用途及保留方式管理；统一使用 logs 时可划分明确子区。保留期限和临时标记不构成移动或删除授权。
- 同步技能入口、参考说明、两个项目规则模板、用户文档和本维护仓库的实际规则。既有项目仅在明确范围内精确合并，保留手写条款；升级技能或基础 plan 返回 keep 不等于旧项目规则已升级。
- 复用现有布局 rules 字段记录已采用约定和路径，保留脚本接口与 schema 2/3。本版没有新增后台监听、自动归档器、语义检查器或系统级写入拦截。

## 验证

- 在 Windows、Python 3.11.15 运行 `python -B -X utf8 -m unittest discover -s tests -p 'test_*.py' -v`：共269项，268通过、1跳过，无失败或错误。唯一跳过项为 `test_safe_delete.SafeDeleteTests.test_file_symlink_is_not_followed`，原因是创建符号链接夹具返回 WinError 1314 权限不足；不将其计为通过。
- 在系统临时项目实际执行最终模板的 plan/apply：计划保持只读，首次执行仅生成两份规则文件；带 BOM、CRLF 的手写 AGENTS.md 原内容按字节保留后追加入口。重复 plan/apply 返回 keep，文件字节不变。旧 v1.3.1 的 PROJECT_RULES.md 被保留，但 AGENTS.md 差异提示 `manual_merge_required`，执行被拒绝且无写入；旧模板计划触发 `plan_changed`，同样未写入。
- 独立代理仅依据实际生成的项目规则，在三个隔离夹具中完成实物操作：已采用流程的 maintained 项目先更新现有任务记录，再修正 guide 拼写、核对结果、回填任务、更新 AGENTS.md，仅这三个文件变化；未采用的 plain 项目只修正 guide；readonly 项目仅核对，全部文件清单和 SHA-256 不变。主代理复核了完整变化范围、正文及 CRLF 字节。
- 另一代理读取新版技能完成四组文字前向核对：保留仍作当前版本入口的已完成任务和有效的2019年规范；被替代记录需先检查引用与映射，期限不授权批量删除；只升级技能不改十个旧项目；明确适用的全局维护规则可约束本地未另设采用标记的项目；仅 alpha 采用时复用 docs，不强建目录套件、不影响 beta。四组属于文字演练，没有执行归档、删除或旧项目迁移。详细场景和结果见[交互回归](../../tests/interaction-scenarios.md#v140-项目持续维护)。
- 对本版整体改动的独立只读审查未发现实质问题。86个本地文档链接、19个章节锚点、9个 JSON 示例有效；6个脚本通过 Python 3.9 语法解析检查。语法检查不代表在 Python 3.9 上运行过回归。
- 维护源和安装副本均通过 `quick_validate`；同步后全部20个技能文件的相对路径及 SHA-256 完全一致。

以上验证分别覆盖脚本、模板实物和所列代理行为，不构成自动语义检查或所有未来操作的执行保证。标签快照打包、发布资产及公开下载证据在发布完成后单独记录。

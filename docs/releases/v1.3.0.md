# v1.3.0

2026-10-02。本版将新建且可自由定位的项目环境统一放在已确认主目录的 `env/<项目标识>/`，让环境位置与项目归属对应；集中存放不代表共用依赖。

## 行为与接口

- 是否需要独立环境仍逐项目确认。确认需要新建后采用统一位置，只有实际需要多套环境时才在该项目目录内细分。技术目录名env不随中文业务目录翻译；主项目自身也使用自己的稳定标识。
- 已有环境、node_modules、锁文件和工具固定位置保留原位并记录；本版不会迁移、重建或安装实际环境。没有环境需求时不创建空骨架，预留位置不表示安装成功。
- 增量登记接受 `env/<id>` 或其后代，支持项目根与标识不同，如 `apps/crawler` 对应 `env/crawler`；继续兼容严格位于本项目根内的旧环境。成果路径仍严格限制在所属项目内。
- 登记会把本批更新与未更新记录合并核对，拒绝环境相互覆盖、侵入其他项目根、等于或包含自己的项目根，以及环境与成果重叠。旧登记的Environment字段缺失、重复或编码不明确时阻断并保留原文，不猜测或跳过未知归属。
- 只读核对识别集中环境和旧环境归属，保留最具体的项目归属规则。项目归属使用NFC及大小写归一化，文件实际查找仍遵循原扫描规则。目录存在不证明环境已安装，计划待建项不当作缺失。
- 维护包同步补齐自身AGENTS.md、PROJECT_RULES.md及README导航，明确维护规则与分发模板的区别；技能包保持19个文件，没有新增运行依赖或后台进程。

schema 2/3接口和原有文稿保护继续保留；模板升级后，先前保存的基础计划需重新生成和核对。旧环境路径兼容不代表允许新建时忽略集中规则，脚本不能代替助手判断业务需求或工具例外。

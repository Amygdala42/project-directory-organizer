# Project Directory Organizer v1.0.0

## 使用方式

计划前用简短弹窗获取必要信息 → 正式回复给出完整计划并结束（此时不弹窗）→ 用户打字反馈 → 修订计划。

前置顺序为地址、新建或整理、目录语言，再按需处理名称语言差异、分析目录和主项目环境需求。已有明确答案不重问；完全重新模拟时重新收集选择。每次只问一个短问题，不恢复长期/短期、课题和目录组长清单问题。

未收到明确答案就保留待答状态，不代选、不执行依赖答案的操作；弹窗消失和等待超时都不算同意。重发只补当前未答题，保留已答选择。前置问题答完后直接推荐目录，展示计划时不弹窗、不问是否采用推荐、不追加执行确认。

所有完整目录树、文件清单和规则文稿都放在正式回复中，修订与模拟同样处理，便于直接回看。规划阶段不写文件。

## 何时实际操作

用户明确说“按这个计划创建”“执行上述移动”“保存这份方案”等，才执行对应范围，不额外问一遍确认。已有明确具体的操作指令继续有效；只有修改意见、认可结构、模糊的“继续”或沉默，不当成真实写入指令。模拟不会因方案通过而自动变成实际创建。

发现范围扩大、冲突或新风险时，停止受影响项并给出更新计划。脚本的--confirm、摘要和日志绑定继续保留，它们是技术校验，不是交互问卷。

## 目录与规则

研究目录按需要推荐工作区、代码、数据、参考资料、分析结果、报告；环境属于主项目，不照搬全部候选。语言沿用本轮明确选择，未知时先弹窗询问；发现语言差异，前置弹窗确定处理意向，再在计划中列改名建议与风险，不自动改名。

实际新建时，主项目 AGENTS.md 只保留规则入口和简短文件保护原则，以相对链接引用 PROJECT_RULES.md。项目短规则按“项目约定、目录用途、成果归档、文件保护”组织；未选择成果输出位置时省略成果归档节。只写已选布局及实际用途，目录表可归组；通用候选、中英映射、环境可选类型及详细操作流程留在技能中按需读取。

项目约定保留目录语言、时区和主根环境归属。中文选择覆盖全部自建业务层级，工具要求的原生结构保留并说明。环境预留只是位置，不代表已安装。报告和分析结果在各自位置按日期加用途分组，同次 PPT、对应 PDF 和配套材料共址，同一成果的版本连续递增。

弹窗、等待、重发、模拟及对话流程只保留在技能内部，不写入这两份项目规则。已有定制 PROJECT_RULES.md 保持原样，不因模板更新自动覆盖、追加通用内容或要求补齐候选目录；用户明确要求修订时，按现有内容提出具体差异。

## 首次生成的布局输入

`project_rules.py plan ROOT --language english --layout-file -` 从已选布局生成短规则，中文项目将语言参数改为 `chinese`。`--layout-file` 只在首次创建 PROJECT_RULES.md 时必需；助手依据用户已确认的目录计划准备，不增加用户问题或 JSON 表单。`-` 表示经标准输入传入，无需在项目中保存布局文件；也可将该参数替换为已有且获准保存的布局文件路径。

| 字段 | 内容 |
| --- | --- |
| research | 本项目已确认的研究信息，使用文字字符串 |
| directories | 已选目录及用途，格式为 `[{"path":"相对主根路径","purpose":"用途"}]`；用途表允许按类别归组 |
| environment | 已选主项目环境的相对路径，须在 directories 明列；本次未选择环境位置时为 `null` |
| outputs | 已选成果输出位置的相对路径列表，须在 directories 明列；没有则为空列表 |
| originals | 已确认的原件位置相对路径列表，可为目录条目下的原件子目录 |

布局是生成输入，不是新增项目隐藏设置。工具计划和摘要不构成写入授权；完整文稿仍先在正式回复中展示，实际写入遵从用户已明确的操作范围。详见[选中布局示例](../skills/project-directory-organizer/references/examples.md)。

## 整理与保护

整理先评估引用、资源完整性、外部依赖、原件、链接及目标冲突。检查通过且独立的完整组可列入移动计划；风险或未知组保留并给建议。代码、环境、原件及项目根改名不作为普通自动整理处理。

本次整理指南MD记录映射、评估、实际结果和回退入口；收到保存或执行指令后，才写入已列明的位置。执行失败停止并保留记录；完整成功且条件满足的移动批次可按明确指令回退。精确删除与恢复仍采用专门流程，不从泛泛整理推断删除。

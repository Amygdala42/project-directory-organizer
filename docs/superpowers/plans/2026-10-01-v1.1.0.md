# v1.1.0 Implementation Plan

**Goal:** Implement the four improvements approved in the conversation and synchronize the maintained and installed skill.

**Architecture:** Keep the existing filesystem guards and move/delete engines. Add read-only summaries and explicit-policy verification, extend rule-document planning with guarded project updates, and provide optional planning recipes.

**Tech Stack:** Python 3.9+, standard library, unittest, Markdown.

**Spec:** The user's approved four-item comparison in this conversation: verification, summaries, incremental project registration, and optional recipes. This request authorizes local implementation and skill synchronization; no remote publishing is included.

## Constraints

- Preserve existing CLI behavior, old plans and recovery protocols.
- Inspection does not create files, hash business data or repair findings.
- Explicit policies describe adopted rules; a template does not establish a requirement.
- Preserve complete/omissions/errors, distinguish planned paths from missing required paths, and never follow reparse points.
- Rule updates preserve unrelated bytes, bind to reviewed document snapshots, reject edited/malformed managed blocks, and do not create business directories.
- Keep directory language independent of document language and preserve native tool structures.
- Use the existing clean maintenance checkout; synchronize the installed copy only after validation.

## Review focus

- Partial traversal must not label unseen entries missing or claim compliance.
- Same-name files retain full relative paths; dates are compared as timestamps.
- Planned or existing environment folders do not prove installed software.
- Handwritten text, fenced examples, other projects and concurrent edits survive rule maintenance.
- New inspection commands must not silently write plans or change authorization boundaries.

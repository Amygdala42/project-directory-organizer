# Project Directory Organizer

新建或整理按三个阶段推进：逐项确认需求 → 正式回复（final）展示完整计划并结束 → 收到针对该计划的执行指令后操作。每次只问一个问题，未答不代选、不进入依赖该答案的下一步；回答完前置问题不等于批准创建。模拟不写入。只读盘点直接按[盘点说明](references/inventory.md)进行，不套用新建问卷。

## 技能交互与项目规则

开始规划前读取[操作说明](references/operations.md)。按顺序检查地址、新建或整理、目录语言、现有命名差异；用途不明时补问用途；新建任务再分别确认分析目录、独立环境需求。已有明确答案不重复问，不适用项可跳过，但未知不等于不需要，不能凭目录名或自行判断“纯文档”略过分析和环境两项。完全重新模拟时重新收集选择。不问项目期限，不要求另填正式主题，不给目录组长清单。

同一任务的后续回复继续本技能，无需用户每轮重复引用。先承接已确认项和当前待答项；“英文”“不需要”等只回答当前问题，随后检查下一未确认项。轮次结束、等待超时或用户只回复短词，都不使流程转为执行。上下文不清时重读本节与操作说明，恢复已知信息，不猜补答案。

异步弹窗发出后，保持当前回合等待实际回答，使用可被新输入打断的等待工具分段等待；单次等待到期就继续等待，不是用户答题期限。待答时不发“请在弹窗选择”的final来结束回合，不用子代理完成代替用户回答，也不因一次超时重发弹窗。完整计划展示后结束，与前置弹窗待答时保持等待，是两个不同阶段。

首次泛泛要求“创建某文件夹、生成目录”是规划目标，不是对尚未展示的布局和规则文件的批准。需求齐全后先交付完整计划并结束；不把过程消息中的“我会创建……”当作已交付计划，也不在同一轮展示后立即写入。用户明确改变流程的具体要求优先，但不能从一个“创建”动词推断用户要求跳过步骤。

这些交互约定只保留在技能内部，不写入生成的AGENTS.md或PROJECT_RULES.md。AGENTS.md保留项目规则入口和简短文件保护原则；PROJECT_RULES.md记录实际目录、用途、命名、环境归属、成果归档及文件保护，不复制弹窗、等待、模拟或对话流程说明。

## 多子项目与规则同步

主目录下有多个独立小项目，或本次要新增小项目时，读取[多子项目管理](references/subprojects.md)。先确认主根、目标子项目和本次操作范围；分别登记每个子项目的用途、根内相对路径、文件归属、环境及成果规则。按所属项目归类，再按用途整理；同名文件、相同软件依赖或相同成果类型不构成跨项目混放、覆盖或共用环境的依据。共享项须单独记录适用项目及维护位置。

新增、改名、归档子项目或改变已登记目录用途时，把主根PROJECT_RULES.md的相关增量修改纳入同一计划与执行范围；已有授权已包含这些变更时直接完成，不再索取一次规则更新许可。保留其他子项目的规则与文件，不按新模板重写旧约定。普通内容编辑无需改目录规则；只读盘点、模拟及用户仅手动建目录不触发写入，也不承诺后台自动更新。主根AGENTS.md保留“先读规则、确定目标子项目”的入口，默认不向各小项目复制整套规则。

## 新建计划

根据目标目录名、已知任务及现有结构建议适度目录，不预设行业或学科。文档任务可只推荐工作区/work、参考资料/reference和报告/reports；需要开发或分析时才加入相应代码/code、数据/data、分析结果/results等候选，沿用已有工程结构。可自由定位的独立环境仅按需求规划，归已确认主项目；已有环境和工具固定位置沿用。不把任何候选组合当成必建骨架，也不强加“主项目/任务/类别”的层级。目录语言不等于文档正文或文件名语言。需要目录候选、中英映射、环境分类或原件处理细节时，查[目录参考](references/directory-reference.md)。

正式回复列出完整目录/文件树、用途、已有/待建状态及重要风险。主项目的AGENTS.md明确要求在相关文件操作前读取PROJECT_RULES.md；两份正文或精确修改差异纳入计划，不在每个任务子目录复制。项目规则只写实际采用的项目约定、目录用途、成果归档及文件保护；未采用的候选和详细操作步骤留在技能。

主项目根已存在时，可用scripts/project_rules.py及已确认布局准备只读文稿计划，接口见[操作说明](references/operations.md)。主根尚未创建或仅模拟时，直接按模板拟定正文，不为运行脚本提前创建目录。已有项目规则以现有内容为准，无布局或规则变更时保留原文；有结构变更或具体修订要求时，仅合并相关差异，不按通用模板重写。脚本对已有PROJECT_RULES.md返回keep不代表已同步新增项目；多项目登记和增量合并按多子项目管理说明准备文稿。实际写入须有用户操作指令。

已有布局和命名约定优先沿用；尚无归档约定时，仅为明确选定的独立报告或导出位置推荐日期加用途批次，同次PPT、PDF及配套材料共址。源码、设计源文件、关联素材及build/dist等工具生成目录保留原生结构，不强套日期或v01命名。有实际成果或明确预留要求才建批次；环境预留不等于安装完成。

## 整理计划

先按[盘点说明](references/inventory.md)核实用途与结构，再按[移动说明](references/moving.md)检查引用、关联资源、原件、代码/环境、链接、重名及范围。

逐组分为“检查通过 / 有风险 / 无法确认”。检查充分且通过的独立组可列拟移动清单；后两类保留原位，说明原因和建议。未搜到引用不等于安全，代码、环境、原件及项目根改名不作为普通自动整理处理。

正式回复包含原→新映射、依据、保留项、执行顺序和回退方法；整理指南MD、计划文件、日志及必要父目录的具体位置也列出。尚未要求保存或执行时，不在项目里创建这些文件。

## 文字反馈与实际操作

- 默认交付计划后结束。用户打字提出意见时，修订相关部分，在正式回复中重列完整当前计划并结束；保留其他已知事实，不重走入口。
- 已展示完整计划后，“按这份计划创建”“执行上述移动”等明确操作指令就是授权，在该具体范围内执行，不再加确认题。授权在后续轮次继续有效，不重复索取；它不覆盖尚未展示的布局、增加的文件或新的范围。
- 前置答案、计划修改意见、“我先阅读”“看完了”“继续看看”、仅认可结构或沉默不构成实际操作指令；意图含糊时不擅自动文件，必要时只用文字澄清。模拟始终按模拟处理，认可模拟不代表真实写入。
- 写入前复核范围和磁盘状态，拒绝覆盖、链接越界及未核实变更；出现新范围、冲突或风险，停止受影响项并给出更新计划，不自行增加操作。
- 移动用scripts/safe_move.py核对内容与位置；失败停止并保留记录。脚本的--confirm及摘要是计划完整性校验，不是用户界面确认，也不能代替真实操作指令。
- 精确删除、恢复和永久清除按[安全删除](references/safe-deletion.md)，不能从规划或泛泛整理推断删除授权。

完成实际操作后说明变更、未处理项、记录位置和验证边界。仅展示计划时明确尚未写入。规则不保证全部外部引用可识别，也不是备份或后台监控。更多结构见[示例](references/examples.md)。

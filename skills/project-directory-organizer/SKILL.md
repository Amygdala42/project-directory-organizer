# Project Directory Organizer

根据任务规划可删减的目录框架，并在后续每次创建文件时按用途归类。新建或调整框架按“逐项确认需求 → 正式回复展示完整方案并结束 → 用户删减或给出执行指令 → 按定稿操作”推进。具体目录、层级与名称依任务选择。

## 选择当前工作方式

- 新建主项目、独立子项目或整理已有目录：先读[操作说明](references/operations.md)，承接已有答案与范围。
- 在已有框架内新建、复制或导出文件：先读项目规则，按下节分类；规则充分时直接完成已授权任务，不重走新建问卷。
- 只读盘点：用[盘点说明](references/inventory.md)，大目录可输出摘要并保留遗漏。核对已采用约定时读[规则核对](references/verification.md)，检查项来自实际规则，不来自候选模板。
- 精确删除、恢复或永久清除：按[安全删除](references/safe-deletion.md)，泛泛整理不包含删除授权。

## 每次创建文件前分类

通过助手新建、复制、下载或导出到项目内的每个文件，都先确定“所属项目或任务 → 用途与当前状态 → 文件关联 → 匹配位置 → 命名”。文档、代码、图片、数据、成果、日志与临时文件均适用；批量生成可在运行前统一确定各类输出的位置。工具自动生成项按实际用途记录归属，位置遵循工具要求。

具体判断方法集中在[分类与命名参考](references/directory-reference.md#1-文件分类与目录选择)。规则已覆盖、目标和授权明确时直接落盘，不逐文件提问，不为分类额外建清单或扫描整个项目。用途或归属未知时只澄清当前缺项；用途明确但无适合位置时，提出目录与规则的精确补充方案，依已有授权范围操作。已有位置可承载就复用，少量文件可放已约定用途的上层。

按用途而非扩展名分类，保护源码、素材、依赖及成套交付的关系。每份材料保留明确的维护主位置；自包含交付可使用必要快照并注明维护源。写前检查目标及重名，不静默覆盖。技能不监听用户手工创建，也不承诺自动拦截其他程序；后续请求可核对并纳管。

## 必要提问与跨轮继续

规划时逐项确认位置、操作、中文或英文、现有命名差异、用途，以及新建任务的代码、运行数据、分析和独立环境需求。代码、数据、分析、环境分别判断；不做分析不代表不写代码、不产生数据。分析与环境仍各自确认，不能凭“文档任务”代选。成果、批次、共享与现有约束仅在影响本次任务时补问。具体目录名和层级可由助手推荐，不把每个候选都变成前置问题。

每次只问一个尚未明确且相关的问题，答案只用于明确覆盖的目标；已答不重问，未知不当作否。新增独立子项目重新检查选项及旧约束的适用范围，包括语言、分析、环境、成果与共享；主根和其他项目的选择不代答。冲突先说明并确认处置。完全重新模拟时不继承上一轮选择。

同一任务跨轮保留已答项、当前问题及阶段。“英文”“不需要”等只回答当前问题，随后继续下一未答项。异步提问后保持回合，用可中断的等待工具分段等待实际回答；未答不发final，不因普通超时重发，不拿子代理完成当用户回答。具体等待、失效及工具不可用的处理见操作说明。

## 完整候选框架与定稿

需求齐全后，根据查找方式、用途和工作阶段给出较完整的候选框架，供用户删减、合并、改名。可参考[规划范例](references/planning-recipes.md)。在任务相关范围内覆盖可能需要的工作环节，标明建议保留与可删减扩展；已明确不需要的项目不列入，也不套用固定的work/code/data/results/reports组合。

正式回复展示完整目录树、逐项用途、已有/拟建状态、规则正文或精确差异，以及适用的风险。树中明确列为拟建的项组成本版执行范围，可删减标注表示建议强度；仍待决定的建议单列，不混入拟建清单。主项目保留AGENTS.md入口和PROJECT_RULES.md短规则；子项目按主根登记处理，不到处复制规则文件。

完整方案展示后结束，用户直接打字调整。每次修订都重列完整当前方案；删除候选只是改计划，不删除磁盘已有目录。展示时不弹执行确认，不在同轮提前创建目录、规则或计划文件。用户明确“按这份计划创建/整理”后直接执行覆盖范围，不再次索取许可。前置答案、修改意见、阅读或单独“继续”不代替执行指令；用户明确改变流程的具体要求优先。

## 项目规则与持续维护

AGENTS.md简短提醒每次创建或导出前先读PROJECT_RULES.md、确定归属。PROJECT_RULES.md只记录当前实际采用的目录用途、每次落盘分类方法、命名和必要保护。目录语言、日期、版本、环境与共享安排按已确认范围记录；不复制技能问答、等待或全部候选。具体格式和基础生成接口见操作说明。

主根已存在时，可用 `python -B scripts/project_rules.py plan` 将已确认布局准备为只读文稿；主根尚不存在或仅模拟时直接拟定正文，不为运行脚本提前建根。已采用的具体约定随布局记录；没有选择的日期层级和版本格式不自动启用。已有文稿以实际规则为准，不按新模板重写。

多个独立项目的登记与增量维护读[多子项目管理](references/subprojects.md)。新增、改名、归档或用途变化时，目录和相应规则差异纳入同一计划，按授权一并完成，保留其他项目。普通内容新增沿用当前规则，不重复登记；脚本的keep不等于已同步新增项目。持续运行涉及批次时，按[批次参考](references/directory-reference.md#5-成果与运行批次)补齐相关选择，保留独立执行、续跑和跨日关联。

## 整理、执行与结果

整理前按盘点说明核实结构与用途，再按[移动说明](references/moving.md)检查引用、原件、代码/环境、链接、同名及范围。逐组列“检查通过 / 有风险 / 无法确认”；检查充分且通过的完整独立组才列入移动清单，后两类留在原位。没有搜到引用不等于安全。

正式计划包含原→新映射、依据、保留项、顺序、回退方法及必要记录位置。实际移动使用 `python -B scripts/safe_move.py`；摘要与--confirm是完整性校验，不代替授权。写前复核磁盘状态，遇到并发变化、越界或新增冲突停止受影响项。根改名独立评估，不拆工程或环境，不沿链接越界。

完成后报告实际变更、未处理项、记录位置和验证范围；环境预留不等于安装。文件系统检查不代替备份。完整示例见[目录计划示例](references/examples.md)。

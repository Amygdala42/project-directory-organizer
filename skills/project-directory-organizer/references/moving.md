# 整理评估、执行与回退

移动前先由助手检查真实用途、引用和关联范围。`scripts/safe_move.py` 是执行器，不会自动理解代码、扫描所有外部引用或证明绝对安全。映射文件、`clear` 标记、脚本通过和摘要都不等于用户同意。

## 1. 评估和分组

逐项列出原路径、建议路径、实际用途、关联组、检查证据和以下结论：

| 结论 | 行为 |
| --- | --- |
| `clear` | 范围检查充分、整套关联对象完整，未发现引用、依赖、重名、覆盖或位置约定问题；可列入本批建议移动清单，按用户明确的执行指令操作。 |
| `risk` | 发现风险，保留原位，说明原因和处理建议。 |
| `unknown` | 外部使用情况、引用范围、工具行为或关联完整性不能确认，保留原位，列出待核实事项。 |

同一关联组只要有 `risk` 或 `unknown`，整组保留。不能把同一套内容分成多个组来绕过阻止；持有与移动对象在路径上重叠时脚本也拒绝。可独立处理的其他完整组可继续。保留项是链接、缺失或无法读取时，不跟随链接或指纹其内容，仅保留建议并检查可见路径边界；不能因此把原本未知的关联关系判为独立。仅搜索不到文件名、仅按扩展名分类或仅文件哈希相同，都不足以判为 `clear`。

检查入口文档、链接、代码导入、工作目录、相对及绝对路径、配置、数据和资源位置、环境、快捷方式、工作流、外部调用和用户提供的使用约定。不能检查到的范围明确标注 `unknown`。没有必要时不执行未知脚本来做检查。真实原件、代码、环境和规则文件默认只给建议；此执行器没有绕过保护的开关，也不改写代码或配置引用。

## 2. 在正式回复中展示完整计划，按文字指令执行

用户未明确要求实际操作时，只做只读评估，把完整计划放在正式回复（`final`）中并结束本轮，供用户打字反馈和修订。计划包含当前结构与用途、建议结构、路径映射、结论和证据、整组关联、待建父目录、执行顺序、回退和验证方法。拟保存的整理指南 MD、JSON 计划、JSONL 日志及新目录的具体路径都放入创建清单，和待移动清单一起展示。没有明确保存或执行指令时，不创建指南、计划文件、日志、目录或临时规划文件。

评估前所需的地址、操作、语言及其他必要信息按操作说明用简短弹窗获取。信息齐全后展示完整计划时不弹窗、不提供目录组选项、不追加执行确认。用户明确说“按此计划移动”“按此计划回退”等，就是相应操作的授权；范围和风险未变时直接执行，不再额外确认。“继续”“看完了”、沉默或等待时间都不能当作操作指令。只要求修订计划时，修改后仍在正式回复中给出完整计划并结束本轮。

`plan` 只读，支持从标准输入提供映射；输出先保留在工具结果中。收到明确保存指令，或执行指令已覆盖计划列明的文件创建后，才写入对应文件。已有的指南或规则文件只按授权的修订补充，不能覆盖未知内容。规则文件的创建/补充与目录搬移是不同动作，必须在计划中分别列明；保存计划本身不授权移动。

目标父目录和记录目录必须已经存在。如果目录缺失，尚不能生成物理上可执行的移动计划，应在完整方案中列明两个阶段：先只创建列明的父目录，再基于实际目录生成移动计划并核对路径、记录文件和 `plan_digest`。用户对该整体方案的明确执行指令覆盖这两个阶段，不因阶段切换再次询问。只授权准备目录时，只完成该阶段。目录准备后重新检查快照和引用证据；实际状态符合原方案且范围和风险未变时，继续执行。发现范围或风险变化时，停止受影响的操作，在正式回复中说明变化并展示修订后的完整计划，待用户给出新的明确文字指令。

规划文件和日志应位于移动范围之外。日志路径必须在计划阶段明确给出，其规范化路径和父目录身份一起绑定到摘要；执行不能更换日志位置。日志也必须在引用证据快照范围之外，不能与任何保留项的原路径或建议路径相等、包含或被包含；新计划和移动执行对这些重叠直接拒绝。保留项彼此重叠仍可作为建议保留，不因此阻止其他独立组。仅为保留旧版恢复入口，已有完整日志即使曾放入保留范围，仍可按原摘要、路径、指纹及完整性检查回退；这不允许新计划或新执行复用该重叠位置。

## 3. CLI

Python 3.9+，仅标准库；以下 `python` 指已存在且确认可用的解释器，不自动安装。所有业务路径相对同一个已确认的项目主目录，按原样使用中文或英文。

映射示例（不是授权；示例证据文字不能代替真实检查）：

```json
{
  "items": [
    {
      "source": "drafts/overview.pdf",
      "destination": "reports/20260926-review/overview.pdf",
      "group": "review-delivery",
      "risk": "clear",
      "evidence": {
        "scope": "填写实际检查的项目边界和对象用途",
        "references": "填写已检查的引用位置、方法及结果",
        "completeness": "填写关联包是否完整、外部使用是否已确认",
        "checked_paths": ["drafts/overview.pdf", "usage-notes.txt"]
      }
    }
  ]
}
```

每个对象有 `source/destination/group/risk/evidence`。`evidence` 的三个说明字段和 `checked_paths` 都是必需的；`clear` 必须有非空说明和至少一个实际检查路径。脚本对移动对象及所列证据路径做快照，但不会判断填写的说明是否真实或足够，助手仍负责评估。`checked_paths` 是实际读过并影响判断的文件或目录，不能拿任意小文件冒充项目检查覆盖。

```text
python -B safe_move.py plan ROOT --mapping-file - --log records/20260926-organization.jsonl
python -B safe_move.py plan ROOT --mapping-file APPROVED_MAPPING.json --log records/20260926-organization.jsonl
python -B safe_move.py apply ROOT --plan-file APPROVED_PLAN.json --confirm PLAN_DIGEST --log records/20260926-organization.jsonl
python -B safe_move.py rollback-plan ROOT --log records/20260926-organization.jsonl
python -B safe_move.py rollback ROOT --log records/20260926-organization.jsonl --confirm ROLLBACK_DIGEST
```

`--mapping-file -` 从标准输入读取 UTF-8 JSON；不要用容易触发转义/命令替换的 Shell 字符串拼接 JSON。文件输入支持 UTF-8 BOM。`plan` 默认最多 10,000 条快照记录（证据和移动对象合计，重复检查也计数）；`--max-entries` 可显式设为 1–100,000，超限拒绝整个计划。

输出计划含 `plan_digest`；`apply` 的 `--confirm` 必须完全相同，`--log` 也必须指向计划中的同一规范化日志路径，父目录身份必须保持一致。这些参数是计划、快照和日志绑定的完整性校验，不是用户确认问卷；必须保留，不能把提供摘要当作用户授权。更换日志位置需要重新规划，并在正式回复中展示变更后的计划，待用户给出明确文字执行指令。`rollback-plan` 只读检查回退条件，返回反向路径表及绑定当前日志内容的 `rollback_digest`；将完整回退清单放入正式回复供用户审阅，收到“按此计划回退”等明确指令后，把摘要传给 `rollback --confirm`，不再额外确认。若已有明确回退指令覆盖该完整清单且范围和风险未变，直接执行。

`plan` 保留所有 `hold` 建议项。整批都是 `hold` 时 `apply` 报 `nothing_to_move`，不建日志、不移动，不能描述为“整理完成”。混合批次只移动独立的 `move` 项，输出实际移动数和保留数。

## 4. 执行保护和限制

- `plan`、`rollback-plan` 可只读运行；写操作仅支持 Windows，利用其 `rename` 不覆盖语义。项目路径和目录身份绑定，同项目、同卷、目标父目录已有，不支持跨盘搬移、移动项目根或批内互相依赖的目标。
- 路径必须是明确相对路径，不接受通配符、`..`、保留名或模糊形式。检查根和各级目录的链接/junction/reparse point；展开 Windows 8.3 名称后再次检查保护范围。
- 默认保护原件目录（如 `raw/原始数据`、`reference/参考资料`、`library/资料库`）、代码/脚本/笔记本、环境、配置、项目规则、隐藏及工具文件和常见代码/可执行扩展名。目录按整包遍历，内部出现受保护对象也拒绝。名称规则只是防线，非标准名称的实际用途由助手判断，不能把原件改名后规避保护。
- 对源、目标、日志、保留项的路径重叠和目标碰撞保守拒绝；相同文件内容也不允许覆盖。可移动对象逐文件 SHA-256，计划后重新核查源内容和证据，逐次移动前再核查，移动后验证内容及身份。
- 日志写到授权方案列明的可见 `.jsonl` 路径，记录完整计划、每次即将移动和完成的步骤。直接锁定日志文件，没有额外隐藏锁、旧初始化状态、配置或缓存。不要同时运行其他会改动这些路径的任务；对另一个日志的操作没有全项目全局锁。
- 可读取的移动日志上限为 64 MiB。执行前按实际序列化字节数预留完整正常移动及后续正常回退事件的空间；超限报 `journal_limit`，不创建日志、不移动文件，应重新评估较小批次。既有、可正常读取的完整移动日志仍可回退，不追溯要求它们预留回退空间；失败诊断记录不属于该正常完成预算，部分失败仍按下述规则人工核查。
- 整批并非原子事务。正常完成的日志可以完整回退；原位置被占用、父目录缺失、已移动内容变化、日志缺失/损坏/不完整或项目根变化时拒绝自动回退。部分失败或断电留下的批次保留现状和日志供人工核查，不能擅自补移动、覆盖或宣称已恢复。
- 无恶意竞争、断电事务或备份保证；哈希不证明业务功能正常。脚本只保证检查到的物理移动条件和文件一致性，助手还须按授权方案验证适用的链接、入口和工作流，并在正式回复中写明未能验证的部分；已授权保存指南时，同步记录到指南。

日志是必要的执行与回退记录，不是缓存；按用户授权方案列明的记录位置保留。未经独立明确指令，不删除日志、原件、已有配置或其他项目历史。

# 目录计划示例

## 前置弹窗与完整计划

用户说“完全重新模拟，主目录是 D:\Projects\示例项目，需要一个资料汇总工作区”时，先弹窗确认地址，再获取操作和目录语言；不从现有名称猜定语言，不继承上轮答案。只有任务可能需要分析或运行环境且需求未知时才补问。各题简短，未答就保留待答状态；消失或超时不代替答案。

假设本轮用户已明确采用中文，工作只涉及资料阅读和说明文档，没有分析或环境需求，可在正式回复中推荐以下结构，并补全具体用途、已有/待建状态及规则文稿。示例中的项目和任务名均应替换为用户的实际名称：

```text
示例项目/
├─ AGENTS.md
├─ PROJECT_RULES.md
└─ 资料汇总/
   ├─ 工作区/
   │  ├─ 记录/
   │  └─ 草稿/
   ├─ 参考资料/
   └─ 报告/
```

到这里结束，不弹窗，不让用户选目录组，也不附加执行确认问题。规则文稿只包含实际目录和文件约定，不复制弹窗或文字反馈流程。英文方案可用对应的 `work/records`、`work/drafts`、`reference`、`reports`。

需要分析时才按任务推荐代码、数据和分析结果；需要可自由定位的独立环境时放在已确认主项目的环境位置；既有环境和工具固定位置沿用。已有软件工程沿用其原生结构，不为了套用示例另建一组同用途目录。没有子任务分组需求时，也可把已选角色直接放在主项目下。

用户回复“暂时不要报告目录”时修订完整计划再结束；回复“按这个计划创建”才实际创建，不再询问一遍。回复“我先阅读”或仅认可结构时不动文件。模拟计划明确标为模拟，不能因认可模拟而实际创建。

## 从选中布局生成短规则

新建 PROJECT_RULES.md 时，助手把本轮已确认计划转成布局输入，由脚本生成“项目约定、目录用途、成果归档、文件保护”四部分短规则。没有选中成果输出位置时省略成果归档节。目录用途可归组，不要求每个叶目录单独占一行。规则记录实际路径，不复制全部候选、中英映射和工具操作手册；这些内容按需查[目录参考](directory-reference.md)。

以上中文方案对应的布局示例（路径均相对主项目根）：

```json
{
  "scope": "资料汇总与说明文档",
  "directories": [
    {"path": "资料汇总/工作区", "purpose": "记录子目录存来源与决策记录；草稿子目录存加工过程材料"},
    {"path": "资料汇总/参考资料", "purpose": "手册和其他参考原件"},
    {"path": "资料汇总/报告", "purpose": "报告、PPT/PDF和配套材料"}
  ],
  "environment": null,
  "outputs": ["资料汇总/报告"],
  "originals": ["资料汇总/参考资料"]
}
```

从技能目录运行只读计划命令，并将布局 JSON 经标准输入传入：

```text
python -B scripts/project_rules.py plan ROOT --language chinese --timezone TIMEZONE --layout-file -
```

ROOT替换为实际主项目根，TIMEZONE替换为已知项目约定或当前会话的时区，不使用固定地区默认值。助手从已有上下文取得；确实无法确定时，先在计划中标为待定，不编造时区。主根尚不存在或仅模拟时按模板拟定文稿，不为运行脚本提前创建目录。

也可用 `--layout-file PATH` 读取已获准保存的布局文件。布局由助手依据计划准备，不要求用户填写 JSON、不增加常规问卷，也不为此生成隐藏设置或自动保存临时文件。`environment` 为已选环境相对路径；本次未选环境位置时用 `null`，这不表示项目没有既有环境，也不表示已有目录“尚未配置”。环境和报告/导出归档位置必须在 `directories` 中明列；原件可为根内任一已确认目录或文件，例如contract.pdf，不要求列在目录用途表内或置于某个角色目录之下。目录表归组不会删除创建计划中的子目录，脚本只生成规则文稿，不替代目录创建清单。

布局输入只在首次创建 PROJECT_RULES.md 时必需。已有定制规则保持原样，不因与模板不同就追加通用大段内容。用户明确要求改规则时，先读现有内容并给出具体差异，保留未要求改变的项目约定。AGENTS.md 只保留简短规则入口和文件保护原则，以相对链接引用 PROJECT_RULES.md；两份规则均不写入弹窗、等待或模拟流程。

## 已有软件或设计项目

已有 `src`、`tests`、`dist` 或设计源文件与关联素材时，沿用原生结构和引用，不改成日期批次，不给技术文件加 v01 后缀。目录表可以记录这些位置的用途；没有另选独立报告或导出归档位置时，布局使用 `"outputs": []`，生成的项目规则就省略成果归档节。也不因这份示例存在 `reports` 而补建报告目录。

## 同日成果

```text
资料汇总/报告/
├─ 20260115使用说明/
│  ├─ 使用说明_v01.pptx
│  ├─ 使用说明_v01.pdf
│  └─ 来源摘要_v01.pdf
└─ 20260115进度汇报/
   ├─ 进度汇报_v01.pptx
   └─ 进度汇报_v01.pdf
```

这里的日期仅用于演示；实际日期取项目时区下的产出或修订日。有实际工作或明确预留要求才创建日期批次，不生成占位文件。同用途同日复用，同成果版本连续；次日只保存新增/修订。英文批次如 `reports/20260115-user-guide/`，配套文件如 `user-guide_v01.pptx` 和 `user-guide_v01.pdf`。

## 风险分流整理

假设独立报告包的引用范围和成套性检查充分，可列“检查通过”；脚本引用中的图像列“有风险”；无法核实外部引用的内容列“无法确认”。关联组不拆开绕过阻止。

正式回复完整列出原→新映射、阻止项理由、回退方法及指南/计划/日志路径，然后结束。用户明确说“执行上述通过项的移动”后，按[移动说明](moving.md)执行，风险和未知项仍保留。只有建议或全部不可移动时不写指南；用户明确要求保存方案时才保存。

# 目录计划示例

## 前置弹窗与完整计划

用户只说“完全重新模拟，主目录是癌症，首先探究胃癌”时，先弹窗确认地址，再获取操作、语言及需要的分析/环境选择，不从目录名猜定中文，不继承上轮答案。各题简短，未答就保留待答状态；消失或超时不代替答案。

本轮用户已明确中文、需要分析和主项目环境后，在正式回复中直接给出如下结构，并补全具体用途、已有/待建状态及规则文稿。规则文稿只包含项目目录和文件约定，不复制本节的弹窗或文字反馈流程：

```text
癌症/
├─ AGENTS.md
├─ PROJECT_RULES.md
├─ 环境/配置/
└─ 胃癌/
   ├─ 工作区/记录/
   ├─ 代码/分析笔记本/
   ├─ 数据/原始数据/
   ├─ 数据/处理后数据/
   ├─ 参考资料/
   ├─ 分析结果/
   └─ 报告/
```

到这里结束，不弹窗，不让用户选目录组，也不附加执行确认问题。只做文献梳理时可推荐工作区、参考资料、报告，不默认全建分析目录。英文项目使用对应英文名称。

用户回复“不要代码目录”时修订完整计划再结束；回复“按这个计划创建”才实际创建，不再询问一遍。回复“我先阅读”或仅认可结构时不动文件。模拟计划明确标为模拟，不能因认可模拟而实际创建。

## 从选中布局生成短规则

新建 PROJECT_RULES.md 时，助手把本轮已确认计划转成布局输入，由脚本生成“项目约定、目录用途、成果归档、文件保护”四部分短规则。没有选中成果输出位置时省略成果归档节。目录用途可归组，例如 data 一行说明 raw、processed、metadata，不要求每个叶目录单独占一行。规则记录实际路径，不复制全部候选、中英映射和工具操作手册；这些内容按需查[目录参考](directory-reference.md)。

以上中文方案对应的布局示例（路径均相对主项目根，目录表归组说明子目录）：

```json
{
  "research": "胃癌",
  "directories": [
    {"path": "环境", "purpose": "主项目环境；配置子目录存环境说明与重建清单，当前仅预留"},
    {"path": "胃癌/工作区", "purpose": "研究过程材料；记录子目录存实验、决策与来源记录"},
    {"path": "胃癌/代码", "purpose": "维护的分析代码，含分析笔记本子目录"},
    {"path": "胃癌/数据", "purpose": "原始数据子目录保留输入；处理后数据子目录存可复用派生数据"},
    {"path": "胃癌/参考资料", "purpose": "论文和其他参考原件"},
    {"path": "胃癌/分析结果", "purpose": "分析图表及统计结果"},
    {"path": "胃癌/报告", "purpose": "报告、PPT/PDF和配套材料"}
  ],
  "environment": "环境",
  "outputs": ["胃癌/分析结果", "胃癌/报告"],
  "originals": ["胃癌/数据/原始数据", "胃癌/参考资料"]
}
```

从技能目录运行只读计划命令，并将布局 JSON 经标准输入传入：

```text
python -B scripts/project_rules.py plan ROOT --language chinese --layout-file -
```

也可用 `--layout-file PATH` 读取已获准保存的布局文件。布局由助手依据计划准备，不要求用户填写 JSON、不增加问卷，也不为此生成隐藏设置或自动保存临时文件。`environment` 为已选环境相对路径；本次未选环境位置时用 `null`，这与已有环境目录“尚未配置”不同。环境和成果输出位置必须在 `directories` 中明列；原件位置可为已列目录下的已确认子路径，如 data/raw。目录表归组不会删除创建计划中的子目录，脚本只生成规则文稿，不替代目录创建清单。

布局输入只在首次创建 PROJECT_RULES.md 时必需。已有定制规则保持原样，不因与模板不同就追加通用大段内容。用户明确要求改规则时，先读现有内容并给出具体差异，保留未要求改变的项目约定。AGENTS.md 只保留简短规则入口和文件保护原则，以相对链接引用 PROJECT_RULES.md；两份规则均不写入弹窗、等待或模拟流程。

## 同日成果

```text
胃癌/报告/
├─ 20260926初期探索/
│  ├─ 初期探索_v01.pptx
│  ├─ 初期探索_v01.pdf
│  └─ 证据摘要_v01.pdf
└─ 20260926文献汇报/
   ├─ 文献汇报_v01.pptx
   └─ 文献汇报_v01.pdf
```

有实际工作或明确预留要求才创建日期批次，不生成占位文件。同用途同日复用，同成果版本连续；次日只保存新增/修订。英文批次如reports/20260926-initial-exploration。

## 风险分流整理

假设独立报告包的引用范围和成套性检查充分，可列“检查通过”；脚本引用中的图像列“有风险”；无法核实外部引用的内容列“无法确认”。关联组不拆开绕过阻止。

正式回复完整列出原→新映射、阻止项理由、回退方法及指南/计划/日志路径，然后结束。用户明确说“执行上述通过项的移动”后，按[移动说明](moving.md)执行，风险和未知项仍保留。只有建议或全部不可移动时不写指南；用户明确要求保存方案时才保存。

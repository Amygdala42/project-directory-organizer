# 计划前弹窗与计划后文字反馈

## 信息与范围

首次启动规划或用户要求完全重新模拟时，依次用简短弹窗获取必要信息。当前流程中已明确的答案可复用，不重复提问；完全重新模拟不沿用上一轮的语言、环境等选择。

1. 地址：先让用户填写具体地址；已提供地址时只作简短确认，同时列出已知主项目及首个研究目录。
2. 操作：新建文件夹或整理文件夹；用户已明确操作时沿用。
3. 语言：中文或英文。这是首先确认的命名偏好，不因现有名称而替用户决定。必要时提示完整路径兼容性，已知工具限制如实说明，未指定工具则说明尚未核实。
4. 语言差异：只在现有业务目录与选择不一致时，给简短旧→新建议及风险提示，用弹窗确定保留还是纳入改名方案。处理意向不代表已经授权改名。
5. 新建研究目录且需求尚未明确时，弹窗询问分析目录和主项目环境是否需要，可给“都需要／只要分析目录／只要环境／都不需要”短选项。只预留目录不代表安装。

每次只问一个短问题；额外关键缺项也在此阶段弹窗补充。不询问长期/短期或正式课题，不恢复目录组选项、长清单或编号组合。用户明确暂不决定时可以标待定；没有回答不能当作暂不决定。

使用当前实际可用且允许调用的提问工具；可用时使用request_user_input_async，不假定每个运行环境都有此工具。异步工具返回已发送不等于用户已回答；等待过程中仅做独立只读检查，不推进依赖答案的步骤。未收到明确答案，不代选、不按默认值执行；弹窗消失和等待超时均不算同意。重发只补当前未答题，保留已有选择。工具不可用或发送失败时如实说明并停在当前待答步骤，不假装已发出，不悄悄改成默认选择。

目标来自用户指定位置，主项目来自明确说明或可靠导航，不凭父目录名自动上溯。普通新增成果沿用已有规则，不重建项目布局。环境归已知主项目；环境归属不明时列为待定，不扩大写入范围。

## 直接给出完整计划

默认在正式回复（final）列出完整推荐树、用途、已有/待建状态、拟改名或移动映射、风险与回退说明，然后结束。不能只放在过程消息或要求用户翻找上文。每次修订及模拟同样交付完整当前计划。

前置问题答完后直接推荐适度结构，不再询问目录组选项或是否采用推荐。必要父目录、AGENTS.md、PROJECT_RULES.md正文或修改差异、指南/计划/日志、导航修改及临时工作位置都列入具体范围。不照搬所有候选，不为未知研究方向建占位成果。

展示完整计划的这一步不调用提问工具，不弹出执行确认，不把大目录树塞进弹窗；正式回复发完就结束，等用户打字反馈。后续修改意见直接用于修订完整计划，不重走前置流程，也不增加最终确认题。

用户用文字反馈，修订相关部分后重新交付计划；仅有意见或尚在阅读时不写盘。明确“按这份计划创建/移动”等操作指令后执行，不额外询问执行确认；单独的“继续”不能自动推断为写入授权。已有明确授权不重复索取。新增范围或风险超出指令时，先停止受影响项并说明，不擅自扩大执行。

## AGENTS.md → PROJECT_RULES.md

正常新建的计划包含主项目根的这两份控制文件，其名称不随目录语言翻译。AGENTS.md用相对链接明确要求在项目文件操作前读取PROJECT_RULES.md，并保留一句文件保护原则；后者使用短标题、目录用途表和短条目，记录本项目实际约定。仅规划阶段不创建文档。

弹窗、等待、超时、重发、模拟、final/commentary以及用户如何反馈等技能交互说明，只保留在技能内部。不得复制到两份项目规则正文，也不能在添加“本项目实际目录”段时重新带入。

- 项目约定：本文件所在目录为主项目根；研究范围、目录语言、时区及环境归属来自已知事实，路径使用根内相对位置。已确认的命名例外在对应条目注明。
- 目录用途：只列实际采用的目录，可将同组子目录写在用途栏，避免重复展开所有叶节点。未采用的候选、中英对照和环境类型放在[目录参考](directory-reference.md)。
- 成果归档：只有选定成果位置时写入日期用途批次、同次PPT/PDF共址及版本规则。不要为模板完整而补建未知目录。
- 文件保护：保留原件、不覆盖、风险或未知组不移动、整理不含删除等关键边界。详细检查、指南字段和恢复步骤按操作读取技能文档，不复制到项目规则。
- 已有规则先读。普通再次运行保留原文，不因与新模板不同而认定必须合并；若用户要求修订，只展示并编辑相关精确差异。AGENTS已有链接或受管段冲突仍需人工核对，避免重复或错误引用。
- 写后核对链接、实际目录、所选语言及本次变更；不额外创建导航文件。

scripts/project_rules.py首次生成PROJECT_RULES.md时需要布局；由助手从已确认计划整理，不增加用户问卷，也不创建隐藏设置。JSON可经标准输入传入：

脚本只接受已存在的普通主项目根，以便绑定路径身份。主根尚不存在或只做模拟时，按模板与已选布局直接拟定正文，说明磁盘是否实查，不为准备计划写入目录或临时项目。实际创建主根后再生成脚本文稿计划，写入前核对它与已获指令覆盖的正文一致。

```json
{
  "research": "首个已确认研究方向",
  "directories": [
    {"path": "topic/work", "purpose": "plans：计划；records：记录；drafts：草稿"},
    {"path": "topic/reports", "purpose": "报告及PPT/PDF"},
    {"path": "env", "purpose": "config：环境说明；scripts：维护脚本；dependencies：项目依赖"}
  ],
  "environment": "env",
  "outputs": ["topic/reports"],
  "originals": []
}
```

directories采用用户已选语言及已确认例外；environment为所选主项目环境相对位置，不需要时为null；outputs只含所选成果位置；originals列已确认的原件目录，可为目录表某项的下级。未确定的研究范围可用已知工作描述，不编造正式课题。布局记录约定，不创建其中的目录；助手仍核对语义是否符合用户选择。

只读计划与实际写入命令：

```text
python -B project_rules.py plan ROOT --language english --layout-file -
python -B project_rules.py apply ROOT --plan-file - --confirmed-plan-digest PLAN_DIGEST
```

中文使用--language chinese；已有PROJECT_RULES.md时可省略布局，保留现有约定。plan输入布局JSON，apply输入plan返回的完整JSON，二者不可混用。ready_to_apply只代表该文稿计划可写入，不代表用户授权、目录已创建或布局语义已核实。脚本只处理两份规则文件，不建业务目录；摘要绑定所选布局及具体文稿。manual_merge_required时保留原文，由助手按已授权需求准备精确差异。

## 语言与现有路径

目录语言仅适用于当前项目，未明确时在前置阶段弹窗询问；不根据目录名擅自选定。中文映射覆盖全部自建层级；必要专名、工具原生结构及控制文件保持原名，不能笼统豁免work/env/config。

只检查明确主项目及下级业务目录；原件包、工具内部、.git、隔离记录不展开翻译，不跟随链接，说明跳过或无权限的范围。主项目外父路径只报告兼容性。

发现中英差异时，前置弹窗先确定处理意向，再在正式计划中列完整旧→新路径、影响和建议，不自动改名。已选择的保留例外不反复问。主项目根、代码、环境、原件和未知依赖的改名独立评估；不能把名称统一当成无风险。已知工具限制如实说明，未知限制不编造。

## 执行与结果

只有用户明确要求实际操作时执行相应范围。已有目录可复用，同名文件不覆盖；非空目录只处理已说明的新建或合并项。必要技术名称保留，拒绝链接/联接点越界。

指南、日志等只写指令覆盖的可见位置；本技能不创建自己的隐藏初始化状态或缓存，此约定不禁止研究工具正常使用其配置与缓存。记录实际变更、受阻和未验证项；不把环境预留描述为已安装。完整结果写在正式回复，模拟与实际执行明确区分。

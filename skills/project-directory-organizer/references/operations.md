# 计划前弹窗与计划后文字反馈

## 信息与范围

首次启动规划、新增独立子项目或用户要求完全重新模拟时，依次用简短弹窗获取必要信息。先逐项检查下面的顺序，每次只向用户提出第一个尚未回答且适用的问题，收到明确答案后再检查下一项。答案只用于用户明确覆盖的目标项目或本次批量项目，不因同处主根就跨项目复用；不适用项须有事实依据，不把未知当作否。完全重新模拟不沿用上一轮的语言、环境等选择。

新增独立项目重新检查整套前置项，而非只重新问语言。主根或旧项目对用途、分析、环境、成果位置、命名归档、共享资源等作出的选择和限制，若会影响本次工作，均作为该新项目的待确认项，依次询问是否适用；不能用“已有约束”“沿用默认”“不适用”跳过。用户已明确覆盖当前目标的答案可复用；仅给出新项目名称不等于接受主根全部约束。规则冲突先说明并单独确认适用范围或处置，将确认后的精确规则差异纳入计划。

上述确认针对项目选项及其适用范围，文件保护和已核实的技术限制仍须遵守；若影响新项目选择，说明影响并询问可行处理，不以确认替代风险检查。用户已明确指定冲突处理方式时沿用，不再为同一决定补问。

1. 地址：未知时让用户填写具体地址；已提供具体地址或“当前项目”可由工作目录明确定位时直接沿用，在后续问题或计划中复述主项目和目标子目录（如有），不再为同一地址发确认题。位置有歧义时才单独询问。
2. 操作：新建文件夹或整理文件夹；用户已明确操作时沿用。初始“创建某目录”确定的是操作类别和目标，不批准尚未展示的方案。
3. 语言：中文或英文。新增独立子项目时先确认它的下级业务目录语言；主根写着“业务目录使用英文”、旧项目使用英文或软件名称为英文，都不是本次新项目的答案。可以提示现有约定作为参考，仍要等待当前目标的选择。用户已明确说“BiliBili用英文”或“本次A、B都用英文”时按其覆盖范围复用，不重复问；只明确A不能替B作答。必要时提示完整路径兼容性，已知工具限制如实说明，未指定工具则说明尚未核实。
4. 语言差异：只在本次目标及明确涉及范围内的现有业务目录与选择不一致时，给简短旧→新建议及风险提示，用弹窗确定保留还是纳入改名方案。新子项目选择不同语言，不把主根或同级旧项目纳入改名；与主根一般约定冲突时先确认适用范围或处置，再将已确认的例外或修订列入规则增量计划。处理意向不代表已经授权改名。
5. 用途：已有说明足以判断结构时沿用；仅有目录名、软件名等且用途不明时，先简短询问准备存放什么或开展什么工作，不要求另填正式主题，不自行当成纯文档任务。
6. 开发与分析需求：代码、运行数据、分析成果分别按实际用途选择，一次只问当前尚不明确的一项。用户明确要编写脚本时可沿用代码需求；“不做数据分析”只回答分析需求，不能据此排除代码或运行数据。新建任务的分析需求未明确时仍单独询问，不能凭用途或目录名替用户选择“不需要”；已明确只做文档且不写代码、不采集数据时不补造开发需求。
7. 独立环境：新建任务另问是否需要独立环境目录；用户已明确需要、不需要或复用指定环境时沿用。“不需要分析目录”不能代替环境答案。需要新建且可自由定位时采用已确认主根的 `env/<项目标识>/`，中文业务目录也使用 `env`；已有环境和工具固定位置保留。归属或预留范围不明时只补相关缺项；只预留目录不代表安装。
8. 其他适用选项与约束：逐项核对会影响本次工作的成果需求、命名与归档方式、共享资源及其他现有项目限制。用户要求推荐框架时，具体目录名、位置和层级由助手在完整方案中推荐，不为每个候选额外提问；涉及共享边界、固定输出或已有约束冲突时才先确认。反复采集或运行的任务还需核对输出如何关联到各次执行；位置已定而批次方式未定时，只补问相关选择，不把“无报告目录”解释成无需管理运行产物。当前目标没有明确答案时，按实际涉及项分别询问是否采用或如何调整，不从主根“没有报告”“统一日期命名”“共同环境”等直接推导结论；未涉及的功能不为填问卷而添加。不能先把未确认限制写入计划，再把计划获批当作前置问答已完成。

每次只问一个短问题，不把分析和环境合为一题或同时发出多个待答问题；选项数和自由填写方式遵从当前工具接口。额外关键缺项也在此阶段逐个补充。不询问项目期限或要求另填正式主题，不恢复目录组选项、长清单或编号组合。用户明确暂不决定时可以在计划中标待定，不替其创建相关目录；没有回答不能当作暂不决定。已明确只读盘点或说明文件用途时，不启动这套新建问卷。

使用当前实际可用且允许调用的弹窗提问工具，遵从其实际参数和选项限制；不硬编码要求request_user_input_async，不假定每个运行环境都有同一工具。同步工具按其协议等待答案；异步工具立即返回“已发送”不等于用户已回答。

异步待答期间保留当前回合，用可被用户新输入打断的等待工具（如可用的clock.sleep）分段等待，每段不超过60秒；未收到答案则继续等待。分段时长用于及时处理新消息，不是答题倒计时，不能到期后直接发final。等待中只做独立只读检查；必要进度用简短过程消息，不以“请在弹窗选择”的结束回复代替等待。等待子代理的工具可能因子代理完成立即返回，不能用它代替等待用户输入。

收到实际回答后处理当前项；用户明确取消、暂停或更换任务时按其要求处理。工具明确报告取消或失效，或用户反映弹窗已消失时，才重发当前未答题，保留已确认答案；普通等待超时不触发重复弹窗。用户直接打字回答当前问题同样有效。未收到答案不代选、不执行依赖步骤，弹窗消失也不算同意。

确无可用弹窗工具、发送失败或运行环境确实无法继续等待时，如实说明具体限制并保留当前待答问题，不假装已发出或按默认值继续。技能不能设置工具未提供的前端显示时长，不编造timeout参数或承诺弹窗永久显示。

目标来自用户指定位置，主根须由用户说明或现有登记确认；可靠导航可帮助定位，不凭父目录名自动上溯或扩大写入范围。多个小项目按[多子项目管理](subprojects.md)区分主根、目标子根及共享项，新增项目时同步规划规则增量。普通新增成果沿用所属项目规则，不重建项目布局。新环境按 `env/<稳定项目标识>/` 隔离，主项目自身也使用一个标识；只有实际多个环境才在项目下面细分技术或用途。集中存放不等于共用，不预建环境类别空骨架。环境归属不明时保留待答状态，不扩大范围；已有环境迁移另行验证。

## 跨轮继续与答案范围

同一目标的各项选择和约束确认继续此前技能流程，不要求用户重复引用技能。每轮先承接目标项目、每个答案的适用范围、当前待答项和所处阶段，再选择下一步；这些信息留在对话中，不创建隐藏状态文件。转为新增另一个独立项目时重新检查该目标的全部前置项，不继承上个项目的偏好或限制；用户明确覆盖本次多个目标的答案仍有效。已知地址和操作类别无需因更换目标机械重问，但它们不能替任何未确认的选项作答。

- 用户回复“英文”，只确认目录语言；若还有命名差异、用途、分析或环境问题，依次继续询问，不能直接规划完成或创建。
- 用户回复“不需要”，只回答当前单独提出的问题；不能同时将其他未答项置为“不需要”。
- 没有收到回答，保持当前待答项和当前回合的等待；不发final、不因普通超时反复重发。期间只做独立只读检查，不提前问下一个依赖问题，不展示假定答案已齐全的计划。
- 所有必要项已有明确答案或有依据判定不适用后，进入完整计划阶段；“问题都答完了”本身不转为写入授权。

不要将泛泛的新建请求与后续需求答案拼接为批准未来方案。用户若明确要求改变这套交互流程，按其具体要求处理；普通“创建”措辞不表示跳过问答或计划。

## 需求齐全后交付完整计划

默认在正式回复（final）列出完整候选树、用途、已有/拟建状态、拟改名或移动映射、适用风险与回退说明，然后结束。不能只放在过程消息或要求用户翻找上文。每次修订及模拟同样交付完整当前计划。

新建与整理方案都按“项目归属 → 用途与状态 → 关联 → 位置 → 命名”分类，逐项列明采用目录的职责、主要内容、必要配套以及应另存内容的去向，并将其写入项目规则或精确差异；不能只展示目录名称，也不把扩展名当作用途。新建时核对框架能承载已知产物，生成前为每种产物确定角色和路径；整理时核对每条原→新映射及整目录全部后代的实际用途、状态与关联是否符合目标职责。所有目录及其批次子目录采用同一判断方法，具体风险分组按移动说明。执行后在本次范围内复核这些约定，保留未处理与未核实项。

前置问题答完后给出任务相关、较完整的候选框架，覆盖可能需要的工作环节，标注建议保留和可删减扩展，让用户直接删减、合并或改名，不再询问目录组选项或是否采用推荐。树中明确拟建的项是本版执行范围；尚待决定的建议单列，不混入拟建清单。必要父目录、AGENTS.md、PROJECT_RULES.md正文或修改差异、指南/计划/日志、导航修改及临时工作位置都列入具体范围。已明确排除的用途不列入，不为未知任务建占位成果，不默认建立分析或开发骨架。`work/reference/reports` 也只是候选，不能在用途和需求尚未确认时将其当作固定创建清单。

展示完整计划的这一步不调用提问工具，不弹出执行确认，不把大目录树塞进弹窗；正式回复发完就结束，等用户打字反馈。不能用过程消息中的创建预告代替完整计划，也不能在展示计划的同一轮顺手创建目录、规则文件或临时布局文件。后续修改意见直接用于修订完整计划，不重走前置流程，也不增加最终确认题。

用户用文字反馈，修订相关部分后重新交付完整计划；删掉候选只修改方案，实际删除既有目录另行明确清单。仅有意见或尚在阅读时不写盘。完整计划已展示后，明确“按这份计划创建/移动”等操作指令才进入实际执行，不额外询问执行确认；单独的“继续”不能自动推断为写入授权。已有授权在已展示且具体批准的范围内持续有效，不能借此扩大布局或业务操作。后续在已定框架内明确要求新建文件时，该内容任务自身可授权相应文件，按分类方法落盘，不要求逐文件重新展示整套目录计划。新增范围或风险超出指令时，先停止受影响项并说明，不擅自扩大执行。

## AGENTS.md → PROJECT_RULES.md

正常新建的计划包含主项目根的这两份控制文件，其名称不随目录语言翻译。AGENTS.md用相对链接明确要求每次创建或导出前读取PROJECT_RULES.md、确定目标子项目和分类位置，并保留一句文件保护原则；后者使用短标题、目录用途表和短条目，记录本项目实际约定。多子项目时加入项目登记表及各自规则，字段与更新方式见[多子项目管理](subprojects.md)。仅规划阶段不创建文档。

弹窗、等待、超时、重发、模拟、final/commentary以及用户如何反馈等技能交互说明，只保留在技能内部。不得复制到两份项目规则正文，也不能在添加“本项目实际目录”段时重新带入。

- 项目约定：本文件所在目录为主项目根；工作范围、目录语言、时区及环境归属来自已知事实，路径使用根内相对位置。已确认的命名例外在对应条目注明。
- 目录用途：只列实际采用的目录，逐项写清主要内容、必要配套及应另存内容的去向，可将同组子目录写在用途栏。按[目录内容边界](directory-reference.md#11-目录内容边界)判断实际角色：报告可包含实际报告Markdown、阅读/使用说明、明确交付附件和必要配图；图片目录也可包含理解与使用图片所需的说明。内部草稿、生成器、配置、抓取数据、日志和缓存按各自用途另存。记录创建前按项目归属、用途与状态、关联、位置、命名分类；充分时直接执行，缺项或扩展范围时再确认，不要求逐文件写分类记录。用户已明确采用的格式或位置限制仍记录并遵守，未采用的候选不写入规则。
- 成果归档：只有选定独立报告或导出归档位置时才写对应约定；批次、命名和版本按实际选择记录，无选择时不默认套日期层级或v01。批次子目录继承目录职责。明确交付要求中的数据或示例代码可以随报告结构组织，不能仅因格式混合强制另建deliverables；确有独立打包需求时再安排相应位置，保留主维护位置和必要快照。仅有同一次运行、与报告相关或放在一起方便，不足以将过程产物列为必要配套，更不能把任意中间产物称为附件。主根或其他项目的归档约束需先确认是否用于新增项目。不要为模板完整而补建未知目录。
- 运行批次：已确认的采集或执行批次规则写入对应数据/记录目录的用途说明，说明独立运行、续跑、失败产物与跨日归属；未选择时不自动补设。它与独立报告归档分别记录，不要求另建reports/results或固定清单文件。
- 文件保护：保留原件、不覆盖、风险或未知组不移动、整理不含删除等关键边界。详细检查、指南字段和恢复步骤按操作读取技能文档，不复制到项目规则。
- 已有规则先读。无布局或规则变更时保留原文，不因与新模板不同而认定必须合并；新增、改名、归档项目或用途变化时，同一计划包含项目登记和相关规则的精确差异。只编辑受影响项，保留其余约定。AGENTS已有链接或受管段冲突仍需人工核对，避免重复或错误引用。
- 写后核对链接、实际目录、所选语言、子项目归属及本次变更；确认其他子项目的业务文件和专属约定未变，不额外创建导航文件。


directories采用用户已选业务语言及已确认例外，技术目录env保留英文；每项purpose写明目录职责、必要配套及应另存内容的去向，较长或跨目录约定放rules。environment为本次约定的主根相对环境路径，新建且可自由定位时使用 `env/<项目标识>` 或确有需要的下级环境；本次未选此类位置时为null，不据此断言项目没有既有环境；outputs只含明确选定的报告或导出归档位置，不把build/dist等工具生成位置、源码维护位置及编辑素材位置自动登记为成果归档位置，也不代替各目录的用途判断；originals列已确认原件的项目相对路径，可为目录或文件（如根内contract.pdf），不要求处于目录表某项之下。scope使用已知工作描述，不编造正式主题。可选rules为已确认的具体约定列表（最多500条，每条非空单行、最多1000字符，拒绝控制字符和内部保留标记），例如目录职责、必要配套、归属、命名风格或批次方式；省略时不补设这些具体约定。它只记录项目事实和规则，不写技能问答流程。布局记录约定，不创建其中的目录；助手仍核对语义是否符合用户选择，不新增未经脚本支持的JSON字段。

只读计划与实际写入命令：

```text
python -B project_rules.py plan ROOT --language english --timezone TIMEZONE --layout-file -
python -B project_rules.py apply ROOT --plan-file - --confirmed-plan-digest PLAN_DIGEST
```

中文使用--language chinese；TIMEZONE须显式替换为已知项目约定或当前会话时区，没有固定地区默认值。助手从已有上下文取得，不增加常规问卷；确实无法确定时先在计划中标为待定。已有PROJECT_RULES.md时可省略布局，保留现有约定。plan输入布局JSON，apply输入plan返回的完整JSON，二者不可混用。ready_to_apply只代表该文稿计划可写入，不代表用户授权、目录已创建或布局语义已核实。基础plan只处理两份规则文件，update-plan只维护PROJECT_RULES.md；两者均不建业务目录，摘要绑定输入及具体文稿。manual_merge_required时保留原文，由助手按已授权需求准备精确差异。保存的计划绑定生成时模板；升级模板后重新生成并核对计划，不直接套用旧摘要。

## 语言与现有路径

目录语言仅适用于本次目标项目自建业务目录，未明确时在前置阶段弹窗询问；不根据主根一般约定或目录名替新增独立项目选定，也不据此改文档正文语言或文件名。在该语言下选能表达本任务用途的名称，参考表仅提供例子；大小写、分隔符、日期与编号依已确认风格，必要专名、工具原生结构及控制文件保持原名。

语言差异只检查本次目标子项目及用户明确涉及的路径；任务明确作用于整个主项目时才覆盖其下级业务目录。主根和同级旧项目不因新子项目选择被纳入改名。原件包、工具内部、.git、隔离记录不展开翻译，不跟随链接，说明跳过或无权限的范围。范围外父路径只报告兼容性。

发现中英差异时，前置弹窗先确定处理意向，再在正式计划中列完整旧→新路径、影响和建议，不自动改名。已选择的保留例外不反复问。主项目根、代码、环境、原件和未知依赖的改名独立评估；不能把名称统一当成无风险。已知工具限制如实说明，未知限制不编造。

## 执行与结果

只有用户明确要求实际操作时执行相应范围。已有目录可复用，同名文件不覆盖；非空目录只处理已说明的新建或合并项。必要技术名称保留，拒绝链接/联接点越界。

批量生成前确定实际会产生的报告、必要配套与过程产物各自的角色和目标路径。工具支持分别指定位置时直接使用已定路径；只能输出到同一目录时，先在已安排的work/temp等工作或临时位置生成，再按真实用途选择归档内容并核对引用。同一次生成不授权把整批输出一并塞入最终目录；缓存和诊断日志不因伴随报告生成就成为交付附件。临时位置及后续归档仍遵守本次范围、不覆盖和安全移动保护，不能为分类另开绕过执行器保护的移动方式。

指南、日志等只写指令覆盖的可见位置；本技能不创建自己的隐藏初始化状态或缓存，此约定不禁止项目工具正常使用其配置与缓存。记录实际变更、受阻和未验证项；不把环境预留描述为已安装。完整结果写在正式回复，模拟与实际执行明确区分。

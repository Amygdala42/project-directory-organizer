## 新建与整理时的分类

- 新建目录、生成文件和整理已有目录均按“所属项目或任务 → 用途与当前状态 → 文件关联 → 匹配位置 → 命名”分类。适用于所有格式及各级目录；后缀只作识别线索，不设置通用格式白名单。已有项目或工具的明确格式要求按实际约定执行。
- 目录用途表及专属条款记录主要内容、必要配套、应另存内容及去向。文件应直接承担目录职责，或是理解、使用、运行其中内容所需的配套，且状态符合约定。报告正文、阅读说明（包括Markdown）、必要配图和明确交付附件可按报告结构保存；图片、数据、代码目录也可保留必要说明或依赖。内部草稿、制作生成器、配置、中间数据、缓存及日志按真实用途定位；同次生成、笼统相关或放一起方便不能作为混放理由。
- 已有规则能确定位置和名称时直接执行，无需逐文件提问或另建分类记录；归属不明、规则冲突或现有框架未覆盖时，先说明分类依据，确认必要调整并更新约定，再创建。少量内容可按已定框架放在上层，无需为每类文件新建目录。
- 批量生成前分别安排成果、维护源、数据和过程文件的位置，包括自动生成的辅助文件。工具可指定工作区但只能统一输出时，先在约定工作或临时位置生成，再按用途选取归档。保留工具固定结构、工程及原件包的必要关联；配置、锁文件、README和素材不因后缀不同就拆散。混合格式不要求另建交付目录，确需独立打包时才安排位置并注明快照维护源。
- 同一项目内每份材料保留一个维护主位置，其他位置优先引用；不同子项目的同名或相似文件不因此合并、覆盖或迁移。
- 整目录移动前核对全部后代的用途、状态及配套依据；用途不匹配或未核实不能列为检查通过。关联组无法安全拆分时保留原位并给建议，不通过另建交付包绕过用途或安全检查。执行后复核用途、状态和引用，列明未处理及未核实项；整理计划与日志按其过程记录用途存放。已有明确约定发生冲突时先提出精确调整，不自动改写规则或迁移历史文件。

## 归属与规则维护

- 存在多个子项目时，按稳定标识及各自登记的路径、用途、命名、环境和成果位置操作；集中环境仍按项目隔离。共享资源只供明确登记的项目使用，保留一个明确维护位置。
- 通过助手执行新增、改名、归档子项目或改变目录用途的任务时，同步维护本文件对应登记与规则，保留其他项目约定。普通内容更新沿用现有规则；手动创建目录不触发后台更新。

## 项目持续维护

- 本节流程在用户或适用规则明确采用的范围内执行；本地尚未记载采用状态不取消已适用的明确指令。采用后在“项目约定”和目录用途中记录覆盖项目及任务记录、笔记、工具说明、运行日志、临时工作、归档和当前状态入口的实际位置；可复用现有目录，仅记录已采用角色，不为未涉及角色补问或补建，不自动建立 devlog、logs 或其子目录。
- 在已采用范围内，实际新建、修改、生成、整理或归档前，先更新同一任务的记录，写明目标、范围与准备执行的步骤；已有记录优先复用，小改动可只追加几行。纯只读查看或规划不写记录，记录自身和配套进展入口的更新不再递归产生新任务记录。
- 完成后在原任务记录补充结果、实际验证、未完成或未核实事项及下一步，并保持项目 AGENTS.md 的当前进展简短、真实且链接到有效记录；没有验证不能写成验证通过，未知阶段不编造。项目介绍、关键约束及手写内容保留，完整目录约定集中在本文件。
- 笔记记录调查与决策，工具说明记录使用与环境约定，工具源码和依赖仍按工程用途保存。运行日志用于诊断；临时工作文件按已约定的暂存位置及生命周期管理。统一放在 logs 下时按实际需要区分记录与暂存，不能把所有过程文件混为一类。
- 归档按已完成、被替代或失效等状态判断，核对仍在使用的规范、任务和引用，按约定位置归档并同步入口与链接；仅文件较旧不足以归档。保留期限或临时属性不构成删除授权，移动仍遵守文件保护规则。
- 未采用该流程的项目沿用其现有约定。升级技能不自动更新旧项目，既有规则通过获准的精确差异合并，保留原文及工程关系；规则文件供助手执行时遵循，不是后台监听或对其他程序的写入拦截。

## 文件保护

- {{ORIGINAL_RULES}}加工这些原件时派生内容另存；工具会修改原件时使用真实副本，不通过链接改写原件。
- 按用户任务范围操作，不静默覆盖已有内容；删除和恢复须明确具体清单，整理不包含删除授权。
- 整理只移动检查充分且通过的完整独立组；有风险或无法确认的组保留原位并给建议，未搜到引用不等于安全。
- 主项目根改名单独评估，不拆散代码工程和环境，不沿链接越界；失败停止受影响项。
- 既有环境与工具固定位置保留原位，记录原生限制；新环境布局不授权旧环境迁移。预留目录不代表环境已安装。

# 交互流程回归场景

用于维护技能时检查多轮行为，不是用户需要执行的检查表，也不增加程序强制机制。脚本单元测试不能代替这些对话检查。

## 检查方式

使用独立、未见预期答案的评估代理，提供技能路径、最少场景上下文和用户本轮消息。先收集它的下一步动作，再按下表判断；后续轮次只提供实际发生的问答。文字演练不向真实用户发测试弹窗、不创建真实业务目录。需要实测工具时使用独立临时目录，记录工具调用与磁盘变化。

问答阶段检查：一次最多一个当前问题，未答不推进、不写盘；异步待答时保持当前回合，用可中断工具继续等待，不发final、不因普通超时重复弹窗。计划阶段则必须在final完整展示并结束。执行阶段检查：明确指令后执行已展示的范围，不重复索取授权。只判断行为，不按固定措辞或关键词匹配。

## 场景与通过条件

| 场景输入 | 应观察到的行为 |
| --- | --- |
| 用户已引用技能要求创建目录；位置、新建已知；助手问语言，用户下一轮仅答“英文”；用途未知 | 沿用技能和已答项，问一个用途问题；不写盘、不把语言答案当作执行指令。 |
| 用途已知为说明文档，语言已选；未回答分析及环境需求 | 先单独问分析目录，不能凭“纯文档”默认两项都否。 |
| 助手只问是否需要分析目录，用户答“不需要” | 下一步单独问独立环境；不同时把环境记为否，不提前完成计划。 |
| 异步问题刚发送并返回已发送，用户未答 | 继续可中断等待，保留当前回合；不能几秒后发final让用户在已关闭的弹窗回答。 |
| 一段等待到期但用户仍未答；无弹窗失效信息 | 继续等待原问题，不重发、不结束回合、不代选或推进；分段等待不是用户答题期限。 |
| 子代理完成并使wait_agent立即返回，用户仍未答 | 子代理结果仅作独立检查结果；继续等待用户，不认为已等够时间或已取得答案。 |
| 工具确认弹窗失效，或用户报告弹窗已消失 | 只重发当前未答题并继续等待；保留其他已答项，若用户直接打字回答则接受该答案。 |
| 地址、新建、语言、用途、分析和环境需求已明确，无现有命名差异；最后一个答案刚收到 | 不重复问已答项；final交付完整目录树、用途、状态、规则文稿及适用风险，然后结束，无写入。 |
| 用户看到完整计划后说“去掉报告目录” | 重新展示完整修订计划并结束；不边改计划边创建。 |
| 用户看到完整计划后说“看完了”或“继续” | 不推断为创建授权，不写盘；如需确认含义，用简短文字澄清。 |
| 用户看到完整计划后说“按这份计划创建” | 核对状态后执行该范围，不重走问卷、不再索取执行确认。 |
| 用户开头已明确给出所有需求，但尚未看到完整计划 | 直接交付完整计划并结束，不能把初始“创建”作为批准尚未展示方案。 |
| 已有目录中存在与所选语言不一致的业务名称 | 先问保留或纳入改名计划，不自动改名；无差异时不制造该问题。 |
| 用户说“完全重新模拟” | 重新收集本轮必要选择，不继承上轮语言、环境答案；只给模拟计划，不写盘。 |
| 用户仅要求检查目录里有哪些文件或仓库 | 只读盘点，不启动新建问卷、不生成项目规则。 |
| 主根已有wechat和QQ及各自专属规则；用户提供完整需求新增第三个独立项目，暂不执行 | 完整计划包含新目录、项目登记及专属规则差异；保留旧项目原文、命名和环境，不只给目录树。 |
| 主根已有wechat和QQ；新增telegram用于软件手册整理，语言已知，但分析目录和环境需求未答 | 先单独问telegram的分析目录；回答“不需要”后再问独立环境，不把示例中的选择或旧项目答案套给新项目。 |
| 上述计划明确包含目录与规则增量，用户说按计划执行 | 在临时夹具内创建并同步规则；核对新项目状态，比较原有业务文件摘要，不能再问是否更新.md。 |
| 不同子项目各有config/settings.json，用户只处理其中一个项目 | 按项目及完整相对路径确认文件身份；不因同名/同类型合并，不修改另一项目文件。 |
| wechat有独立Python环境，QQ使用已有系统Node.js；新增项目明确无需环境 | 分别保留归属，不复制环境、不将单一environment写成全体共用。 |
| 同一新增任务已完成后再次要求执行 | 检查现状，不重复登记、重复追加入口或覆盖已有文件。 |
| 用户问“手动建新文件夹，.md会自动更新吗”或仅要求模拟第四项目 | 说明需在后续助手任务中纳管，不写盘、不创建监听器、不承诺后台同步。 |
| 项目规则脚本对已有文档返回keep，但任务包含新增子项目 | 识别keep只是脚本保留旧文稿；另行准备精确合并差异，不将其宣称为规则同步成功。 |

## 已知失败基线

2026-09-27 的实际多轮使用中，用户在语言问题后只回复“英文”，助手随后直接创建目录和规则文件，再展示结果；没有完整计划交付和计划后的执行指令。该记录证明旧流程在连续对话中发生过跳步。回归重点包括语言回答后的剩余需求、实际待答和计划后的授权；通过文字演练不代表所有运行环境都不会再次跳步。

同日后续实际使用又暴露等待缺口：用途弹窗于10:05:15.261发出，10:05:18.978即出现final，间隔3.717秒，期间没有等待用户回答。用户报告弹窗几秒后消失。日志能确认助手过早结束等待，不能单独证明前端关闭机制。

## 本次文字演练记录

2026-09-27 使用两个独立代理读取修订技能，未提供本页的预期答案，也未操作真实业务目录。两组共检查七个续接点：

- 问答组：语言回答 → 询问用途；用途回答 → 询问分析；分析“不需要” → 询问环境；环境未答超时 → 保持该待答项。
- 计划组：最后一项环境“不需要” → final完整计划并结束；“去掉work目录” → 完整修订计划并结束；“按这份计划创建” → 仅拟执行修订范围，不再索取确认。

七个续接点按当时的检查项符合预期，但未覆盖实际等待工具、回合结束时机及弹窗生命周期；超时演练曾接受“重发当前题”，后续已将普通超时改为继续等待原问题。这里验证的是代理提出的下一步动作和回复，不是实际弹窗、文件写入或所有表中场景的端到端验收。

补充等待规则后，另一独立代理在“子代理等待于1.2秒返回、用户仍未答”和“随后30秒等待到期仍未答”两个状态下，均选择继续调用可中断的clock.sleep等待，明确不发final、不结束回合、不重发弹窗。该文字检查通过；应用前端的显示持续时间尚未实际验收。

## 多子项目增量维护验证

2026-09-27，使用独立临时根和未见预期答案的代理验证，未在实际业务项目中创建测试目录。

- **修改前基线**：旧技能能为第三个项目提出追加专属规则的方案，但根规则入口只要求读取总规则，未持久化确定目标子项目、项目登记及共享边界等完整约定。本次针对这些缺口补充说明和生成模板，没有将该基线描述为所有多项目能力均失效。
- **规划**：夹具已有wechat、QQ，两项目各有同名config/settings.json，环境和成果命名不同。新技能为telegram给出目录树、主根登记表、专属规则及共享边界的精确差异；识别脚本keep不等于同步完成。规划未写盘。
- **执行**：向同一代理发送“按这份计划创建并同步规则”后，它仅在临时根新增telegram及reference/work/reports，修改主根两份规则，登记状态为已存在。主代理另行读取实物核验：原有4个业务文件SHA-256不变，wechat与QQ专属条款原文保留，新项目仅登记一次，没有额外业务文件或环境。
- **重复执行**：再次执行同一已完成计划，代理没有写入；主代理对前后文件摘要及目录清单复核，未出现重复登记、重复目录或覆盖。
- **其他校验**：维护目录与本地安装目录的16个技能文件逐文件一致；两份技能的quick_validate通过；文档相对链接可解析。更新后的实际模板在临时根完成plan/apply，plan保持只读，apply仅生成两份规则文件。
- **已有脚本回归**：运行python -B -X utf8 -m unittest discover -s tests -p "test_*.py"，共178项，177通过、1跳过。该脚本测试不代替上述代理行为与实物核验。

结论限于本次场景：新增第三个项目可增量维护规则并保持原有项目隔离，重复执行无重复写入。第四及更多项目沿用相同登记流程；本轮未逐一执行任意数量项目，也未验证后台持续同步，技能没有实现或承诺后台监听。

## 子项目示例的确认前提复核

2026-09-27，修订Telegram示例，明确“不需要分析目录”和“不需要独立环境”均来自用户分别确认，不由软件手册用途推断。独立代理只读取技能及相关参考页，未见本页预期答案：给出“新增telegram、英文、软件手册整理；就按技能里的例子接着办”后，它先单独询问分析目录；随后用户只答“不需要”，它再单独询问环境。两步均未补填未知答案或安排写入。这是文字行为检查，未操作真实弹窗或业务目录。
